- **Nothing is sent to an armed model when the link comes up (`tasks/msp/runtime.lua`, `tasks/events/runtime.lua`, `tasks/events/telemetry_bg/tasks.lua`, `tasks/events/telemetry_bg/drain.lua`, `docs/reference/connection-status.md`, `docs/developer/background-tasks.md`, `docs/reference/background-decoder.md`)**:
  - On a new link the handshake and the connect sequence wait until the armed state has arrived over telemetry (the arming flags or the System Status word), or 5 seconds for a flight controller that reports neither, so a model that is already armed when the link comes up is sent nothing until it is disarmed.
  - While the connect sequence runs, the dashboard decodes the armed state from the flight controller's custom telemetry even when the background function script is not running, so an arming during the sequence stops it; the rest of the telemetry still waits for the connect to finish.
