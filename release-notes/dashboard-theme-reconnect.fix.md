- **A reconnect no longer reloads the model's dashboard theme from the SD card (`widgets/dashboard/runtime.lua`)**:
  - Until the flight controller's UID has been read, the dashboard resolves no theme and runs no pending preferences reload, so a model with a theme of its own keeps that theme's modules loaded across the reconnect instead of releasing them for the radio's theme and reading them from the card again seconds later. A flight controller that does not report a UID gets the radio's theme then; a model armed before its UID was read keeps the connection screen until the disarm, when the UID is read again (#1008).
  - Losing the link no longer counts as a preferences change: the per-model file dropping out with the board's id is not taken as a changed file, so no reload runs at the disconnect, the model's theme stays loaded through a link loss on the ground too, and the reconnect runs no extra reload. A change found while its reload is deferred is no longer statted and logged again every second (#1009).
  - A radio setting saved while a preferences reload is deferred, and signalled only by the reload request, is no longer lost when the model's settings are saved too before the reload runs: such a reload reads both files (#1043).
