- **A failed save that may have reached the flight controller offers a restart (`tasks/msp/save_pipeline.lua`, `ui/home.lua`, `docs/reference/saving.md`)**:
  - When a save fails before its settings are stored, after a write was confirmed or sent without an answer, the flight controller may already run some of the new values until it restarts. The *Not saved* notice now says so and offers **Restart FC** beside **Continue**; the restart writes nothing and waits for the board as a save with a restart does. It is offered only with the connection up and the model neither armed nor of unknown arming state, and the restart command goes out only on the flight controller's own fresh answer that it is disarmed, checked again at every send (a message may now carry such a check in the MSP queue, `tasks/msp/queue.lua`). A save whose first write was refused keeps the plain notice.
  - A save step left unanswered for 30 seconds drops the requests its save still had waiting, and the ended save ignores a late answer instead of driving the next save or the restart.
