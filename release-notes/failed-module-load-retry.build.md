- **A module that does not load is asked for again once a second, not on every pass (`tasks/events/telemetry_bg/drain.lua`, `tasks/msp/runtime.lua`)**:
  - The custom-telemetry drain asks again for its decoder table (`lib/rf2tlm_sensors.lua`) or the CRSF module (`lib/crsf.lua`) one second after a failed load, instead of going back to the card for the file on every wakeup, ten times a second. A load that fails once and then succeeds -- for example a pass stopped by the instruction limit while the table loads -- decodes again about one second later (#477).
  - The API version read waits one second before asking again for one of its modules that did not load, instead of asking on every tick. The read stays owed, so a load that fails a few times and then succeeds still connects, about one second later per failed attempt (#471).
